# Model & Token Optimization Policy

AI Context Harness を利用する AI エージェントのモデル選択とコンテキスト消費を最適化するための共通ルール。

## 1. 基本方針

- 品質・安全性・正確性を維持した上で、必要最小限のコンテキストと推論で作業する。
- 最初から高性能モデルを使い続けるのではなく、作業難易度に応じて適切なモデルを選択する。
- モデル名を固定せず、利用可能なモデルの能力を役割に合わせて選択する。

## 2. モデル選択

### 軽量モデルを優先

- ファイル・ディレクトリの探索
- 既存コードの単純な確認
- 定型的な修正
- ドキュメント修正
- lint・テスト結果の確認
- Git status / diff の確認
- 単純なリファクタリング

### 高性能モデルを使用

- 新規機能の設計
- 複雑なバグ調査
- アーキテクチャ設計・変更
- 複数システムにまたがる変更
- セキュリティ・認証・権限・データ設計
- 原因が不明な障害
- 重要な技術判断
- 軽量モデルで解決できなかった問題

### 切り替えルール

1. まず軽量な調査・分析で問題の範囲を特定する。
2. 複雑性・影響範囲・失敗リスクが高い場合のみ高性能モデルへ切り替える。
3. 高性能モデルでの判断・設計が完了した後、単純な実装・検証は軽量モデルへ戻してよい。
4. モデル選択に迷う場合は、トークン節約より失敗リスクの低減を優先する。

## 3. コンテキスト消費

- 必要なファイルだけを検索・取得し、無関係なファイルを大量に読み込まない。
- 大きなファイルは必要な範囲を先に特定してから読む。
- 同じ情報を繰り返し取得しない。
- リポジトリ全体の読み込みを常態化しない。
- Context Harness の `CONTEXT.md` / `STATE.md` / `DECISIONS.md` も、作業内容に必要なものだけ読む。
- 作業開始時は現在状態と次のアクションを優先して確認し、過去履歴は必要な場合だけ参照する。
- 検索 → 絞り込み → 必要箇所の読み込み、の順で調査する。

## 4. 段階的実行

標準的な作業フローは以下とする。

1. **Identify**: 対象プロジェクト・リポジトリ・変更範囲を特定
2. **Inspect**: 必要最小限のファイルを調査
3. **Decide**: 難易度とリスクからモデルを選択
4. **Implement**: 必要な変更のみ実施
5. **Verify**: 変更範囲に応じた必要最小限の検証
6. **Record**: 必要な場合のみ Context を更新

単純な作業では全工程を重く実行せず、作業規模に応じて省略・軽量化する。

## 5. 禁止事項

- トークン削減を目的に必要な検証を省略しない。
- 高性能モデルの使用を目的化しない。
- 軽量モデルで十分な作業を高性能モデルへ固定しない。
- Context Harness に不要な会話履歴・コード全文・ログ全文を保存しない。
