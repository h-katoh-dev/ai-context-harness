# AI Work Policy

AI Context Harness を利用する AI エージェントの、モデル選択とトークン消費に関する共通ルール。

## 1. 基本原則

- 品質・安全性・正確性を維持した上で、不要なトークン消費を抑える。
- 最初から高性能モデルを固定的に使わず、作業の難易度に応じて必要な能力を選択する。
- モデル名や特定ベンダーの仕様には依存せず、「軽量」「高性能」という役割で判断する。
- モデル選択よりも、作業の正確性と失敗回避を優先する。

## 2. モデル選択

### 軽量モデルを優先する作業

- ファイル・ディレクトリの探索
- 既存コードや設定の確認
- 単純な修正・置換
- ドキュメント修正
- 定型的な実装
- lint・テスト結果の確認
- Git status、diff、履歴の確認
- 単純なIssue・TODO対応

### 高性能モデルを使用する作業

- 新規機能の設計
- 複雑なバグの原因分析
- 複数ファイル・複数レイヤーにまたがる変更
- アーキテクチャ設計・変更
- セキュリティ・認証・認可・データ設計
- 要件が曖昧で判断が難しい作業
- 軽量モデルでは解決できなかった問題
- 重要な意思決定や最終レビュー

### 段階的な切り替え

1. まず軽量な調査・探索で対象範囲を特定する。
2. 単純な作業ならそのまま軽量モデルで完了する。
3. 複雑性・影響範囲・失敗リスクが高い場合のみ高性能モデルへ切り替える。
4. 高性能モデルでの設計・判断が終わったら、定型的な実装や検証は軽量モデルへ戻せるか判断する。

## 3. トークン最適化

- いきなり大量のファイルを読むのではなく、構成確認→検索→関連箇所の精読の順で調査する。
- 必要なファイル・行・関連コードだけを読む。
- 同じ情報を繰り返し取得しない。
- 大規模リポジトリでは検索条件を段階的に絞る。
- 変更対象外のコードを長時間分析しない。
- 既存のドキュメントやContextにある情報を再調査しない。ただし現在のリポジトリを最新の事実として扱う。
- テストは変更範囲に応じて、まず関連する最小限の検証を行い、必要に応じて範囲を広げる。
- 出力・報告は簡潔にし、作業に不要な説明を生成しない。
- トークン削減のために必要な調査・検証を省略してはならない。

## 4. 標準ワークフロー

`探索 → 難易度判定 → 必要なモデルで実装 → 最小限の検証 → 必要に応じて追加検証 → 状態更新`

この順序を基本とし、単純な作業では工程を短縮してよい。

## 5. 禁止事項

- すべての作業で高性能モデルを使用する。
- トークン削減だけを目的として重要なコード・設定・Contextを読み飛ばす。
- モデル名や現在の提供仕様を固定値としてContextに保存する。
- モデル選択のためだけに不要な外部調査を行う。
