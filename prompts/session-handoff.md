# Session Handoff Prompt

## 目的
新しいチャットから `ai-context-harness` を使って、既存プロジェクトの現在状態を確認し、作業を安全に引き継ぐ。

## 最初に必ず行うこと

1. GitHub の `h-katoh-dev/ai-context-harness` を確認する。
2. `AGENTS.md` を最初に読む。
3. `projects/README.md` を読み、プロジェクト構成と登録済みプロジェクトを確認する。
4. 現在の会話内容から対象プロジェクトを判定する。
5. 対象が明確な場合、そのプロジェクトの `CONTEXT.md`、`STATE.md` を確認し、必要に応じて `DECISIONS.md` も確認する。
6. 実際の対象リポジトリも確認し、ハーネス側の状態と実リポジトリの状態を照合する。

## プロジェクト判定ルール

- 新しいチャットだからといって、特定プロジェクトへ自動的に紐付けない。
- プロジェクト専用チャットである必要はない。
- ユーザーの発言、対象リポジトリ、プロジェクト名、作業内容から対象を判断する。
- 対象プロジェクトが明確なら、そのプロジェクトのコンテキストを読み込む。
- 複数プロジェクトに該当し得て判断できない場合は、ユーザーに確認する。
- 単なる関連話題や一般的な会話だけではプロジェクト活動として記録・追跡しない。
- ユーザーが明示的にプロジェクトを指定した場合、それを優先する。

## 作業ルール

- 実際の開発・編集作業は対象リポジトリで行う。
- `ai-context-harness` はプロジェクトの状態・判断・継続情報を管理するために使用する。
- ハーネスにソースコードを不要にコピーしない。
- まず現在の `STATE.md` と実リポジトリを確認し、「現在どこまで完成しているか」「何が未完了か」「次に何をすべきか」を整理する。
- 可能な作業は、確認後そのまま進める。不要な確認質問を繰り返さない。

## 作業終了時

意味のある作業を完了したら、必要に応じて以下を更新する。

- `STATE.md`: 現在の状態、直近の完了内容、次の具体的なアクション
- `DECISIONS.md`: 重要な設計・方針決定
- `CONTEXT.md`: 長期的に有効な前提・知識

未完了の作業を完了扱いにしない。

## 禁止事項

- APIキー、パスワード、トークン、認証情報などの秘密情報を保存しない。
- 顧客・勤務先などの機密情報や不要な個人情報を保存しない。
- 雑談や通常のChatGPT利用をプロジェクト活動として勝手に記録しない。
- 対象プロジェクトを推測だけで決めない。
- 過去の判断履歴を理由なく書き換えない。

## 開始時の基本方針

「まず現在の `STATE.md` と実リポジトリを確認し、現在どこまで完成していて次に何をすべきか整理する。その後、ユーザーの指示に従って作業を継続する。可能な作業はそのまま進める。」
